# Live Demo Guide

A 5-minute walkthrough to show the project working. Read the expected output
so you know what "success" looks like at each step.

**Prerequisite:** Docker Desktop is running (check: `docker ps` succeeds).
No SUMO or Python install needed — everything runs inside the container.

On Windows use `.\run.ps1 <target>`; on Linux/Mac use `make <target>`.

---

## Step 0 — (one time) build the image
```powershell
.\run.ps1 build
```
Builds Ubuntu + SUMO 1.27.1 + PyTorch. Takes a few minutes the first time,
instant afterwards. Success ends with `naming to ...traffic-rl-dqn:latest`.

---

## Step 1 — Prove the simulation works
```powershell
.\run.ps1 verify
```
**Expected output (the key lines):**
```
[OK] traci imported successfully (version: 1.27.1)
[INFO] Running 100 simulation steps...
[OK] Completed 100 steps. Simulation time: 100.0 s
[INFO] Vehicles currently in simulation: 16
  ALL CHECKS PASSED
```
→ *Talking point:* "SUMO loads the intersection, vehicles are moving, and the
traffic light is under program control."

---

## Step 2 — Prove the code is tested
```powershell
.\run.ps1 test
```
**Expected:** `18 passed` — unit tests for the reward function and the D3QN
agent (network shapes, replay buffer, epsilon decay, target update, save/load).

---

## Step 3 — The baselines (what we compete against)
```powershell
.\run.ps1 baselines
```
**Expected (avg waiting time, seconds):** fixed-time ~55–65 s, actuated ~7–24 s
depending on scenario. → *Talking point:* "Actuated is a strong, realistic
baseline — not a strawman. This is the bar the RL agent must beat."

---

## Step 4 — The headline result
```powershell
.\run.ps1 evaluate
```
This runs Static vs Actuated vs **DQN** across 3 scenarios × 3 seeds and prints
a mean ± std table. **Expected comparison (avg waiting time):**

| Scenario | Static | Actuated | DQN |
|---|---|---|---|
| balanced | ~57 s | ~19 s | **~12 s** |
| asymmetric | ~65 s | ~24 s | **~16 s** |
| surge | ~35 s | ~7 s | **~6 s** |

→ *Talking point:* "The DQN beats both baselines on every scenario — 75–83%
lower waiting time than fixed-time, and better than even the actuated
controller. It also produces roughly 10× less CO₂."

---

## Step 5 — Show the figures
Open these (they're regenerated by Step 4):
- `results/plots/compare_avg_wait.png` — the money chart: DQN (green) lowest everywhere.
- `results/plots/training_curves.png` — reward climbing then stabilizing = real learning.
- `results/plots/compare_throughput.png` — all controllers clear the same demand

## Step 6 (optional bonus) — Heterogeneous traffic + PCU
```powershell
.\run.ps1 phase7
```
Mixed fleet (car/motorcycle/auto/bus) with IRC PCU-weighting. **Expected:**
PCU-weighted DQN ~22 s vs un-weighted ~29 s → PCU-weighting helps by ~24 %.
Chart: `results/plots/hetero_ablation.png`.

## If asked "show me the code"
- Environment: `env/traffic_env.py` (state/action/step) + `env/reward.py`
- Agent (raw PyTorch D3QN): `agent/dqn.py`
- Baselines: `baselines/`
- Training loop: `train.py`; Evaluation: `evaluate.py`
- Full write-up: `REPORT.md`

## If the demo machine is slow
Everything above uses fast settings. For full-scale numbers:
`.\run.ps1 train -Episodes 300 -SimTime 3600` (takes much longer).
